这是一篇示例文章。仓库里的 `content/posts/` 是正文的唯一来源，列表、摘要、RSS、sitemap、搜索索引与三维卡片都由同一份内容派生，因此把正文替换成你自己的文字并重新构建即可。

## frontmatter 里的字段

每篇文章的身份由 `id` 决定，标题或排序变化都不应改动它。`path` 是规范地址，不能与 `/lab/`、`/tags/`、`/categories/`、`/search/`、`/archive/` 等系统路由冲突。

| 字段 | 作用 |
| --- | --- |
| `id` | 稳定身份，迁移导入的文章使用 `wp-<数字>` |
| `title` / `description` | 列表、搜索与分享用；摘要上限 300 字 |
| `path` | 规范站内路径，发布后保持稳定 |
| `draft` | 为 `true` 时不会进入任何公开产物 |
| `categories` / `tags` | 分类与标签页的取数来源 |
| `legacyUrls` | 旧站地址，用于生成一对一永久重定向 |

## 怎么开始写

1. 复制本文件，改 `id`、`title`、`path` 与正文。
2. 运行 `npm run check:content` 校验字段、路径唯一性与主题引用。
3. 运行 `npm run build` 生成博客、`/lab/` 入口与搜索索引。
4. 运行 `npm run preview` 本地检查阅读、导航与 404。

正文支持 CommonMark 与 GFM：**加粗**、*斜体*、`行内代码`、引用、表格、脚注[^note]与代码块都可以直接使用。

[^note]: 脚注同样会被阅读层正确排版，实现见 `src/article-reader*.ts`。

// 代码块使用 JetBrains Maple Mono 子集，按本站令牌着色

  return `hello, ${name}`;
}
